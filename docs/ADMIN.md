# Веб-панель маршрутизации

Веб-панель меняет серверные правила маршрутизации без редактирования клиентских профилей. Правила действуют для всех устройств, подключённых к этой установке VPN.

В примерах `home-vpn` — имя установки. Замени его, если при создании было выбрано другое имя.

## Доступ

Веб-панель устанавливается только в двойной схеме (`dual`) на российском сервере входа. В одиночной схеме (`single`) панель и её компоненты не устанавливаются; правилами маршрутизации можно управлять через команды `routes`.

1. Убедись, что VPN-клиент недавно обращался к серверу входа по TCP или UDP.
2. Запусти `.\vpn.cmd` и выбери `Показать адрес web-admin`. После установки адрес также печатается автоматически.
3. Для запуска без меню используй `.\vpn.cmd admin --deployment home-vpn --open-browser`.
4. Если браузер не открылся, перейди по напечатанному публичному адресу вида `http://<gateway-ip>:11333`.
5. Начальный логин и случайный пароль находятся в `deployments/home-vpn.env`, строки `ADMIN_WEB_USERNAME` и `ADMIN_WEB_PASSWORD`. Не отправляй этот файл другим людям: в нём также есть секреты VPN.
6. Пароль можно изменить на странице `Доступ`. При обновлении текущий пароль панели не сбрасывается; начальные данные из env после такой смены уже не подходят.

Команда `admin` только показывает или открывает адрес панели и сразу завершает работу. Сервер временно разрешает доступ к панели с внешнего IPv4/IPv6-адреса, с которого недавно приходили пакеты на порт VPN. Если новых пакетов нет, разрешение истекает. Браузер должен обращаться к панели с того же внешнего IP-адреса. Этот допуск ограничивает круг доступных адресов, но не подтверждает успешный вход в VPN и не заменяет логин и пароль панели (Basic Auth).

### Защищённый доступ

Публичный адрес панели использует HTTP, а не HTTPS. Сам факт включённого VPN не гарантирует шифрование этого запроса: клиент может исключать IP сервера из туннеля. Для ввода пароля используй SSH-перенаправление, которое не меняет VPN-профиль и маршруты компьютера:

```text
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:11334:127.0.0.1:11333 root@SERVER_IP
```

Замени `SERVER_IP` адресом сервера входа, `root` своим SSH-пользователем, а последний `11333` портом панели, если менял его. Команда одинакова для Windows и Linux. После входа SSH оставь окно открытым и перейди в браузере на `http://127.0.0.1:11334`. До локального порта трафик остаётся на компьютере; между компьютером и сервером он защищён SSH. Для завершения нажми `Ctrl+C` в этом окне. Если порт `11334` занят, выбери другой локальный порт в команде и адресе браузера.

Обновление с прежних версий не заменяет существующий пароль автоматически. Если остался старый общий пароль, смени его через защищённый доступ. Серверный HTTP-порт сохраняется для совместимости; packet gate не является защитой пароля от перехвата.

Техническая справка: [локальное перенаправление OpenSSH](https://man.openbsd.org/ssh#L). `ExitOnForwardFailure` проверяет создание перенаправления, но не доступность самой панели: её нужно проверить в браузере.

## Примеры правил администратора

| Задача | Выход |
| --- | --- |
| Собственный сервис настроен принимать запросы с IP-адреса российского сервера | `российский сервер` |
| Запросы к собственному сервису должны записываться в его журнале с IP-адресом зарубежного сервера | `зарубежный сервер` |
| Для проверки маршрута тестовый домен закреплён за одним из двух серверов | Выбранный администратором выход |
| Для публичной IP-сети администратор задал единый выход в интернет | Сервер, заданный этим правилом |

В двойной схеме панель предлагает российский и зарубежный выходы. Если выбранный выход недоступен, правило не заменяется автоматически правилом для другого выхода.

Добавляй правило для домена или публичной IP-сети, которым нужен конкретный сервер выхода. Оно имеет приоритет над автоматическим выбором маршрута и применяется ко всем пользователям этого VPN.

## Форматы правил

- `example.com` — только этот домен;
- `*.example.com` — домен и все его поддомены;
- публичный IP-адрес или сеть в формате CIDR, например `8.8.8.8/32` — один адрес или указанный диапазон адресов.

Не указывай протокол, путь страницы или параметры запроса. Для адреса `https://video.example.com/watch?id=1` значением правила будет `video.example.com`.

CIDR используй только когда сервис публикует стабильный диапазон адресов. Частный или локальный диапазон панель отклонит. Слишком широкая публичная сеть может затронуть посторонний трафик, поэтому начинай с доменного правила или отдельного `/32`.

## Применение

После сохранения новые настройки проверяются и применяются на сервере входа. Если запуск не проходит, сервер возвращает предыдущие правила. Ссылку подключения VLESS (URI) менять или импортировать заново не нужно.

Применение правила перезапускает серверный `sing-box`, поэтому активная загрузка или воспроизведение может кратко переподключиться. Сохраняй правила между важными загрузками, затем повтори запрос к нужному сервису. Отключать VPN или менять профиль не требуется.

Если главная страница открывается, а видео, изображения или авторизация не работают, сервис может использовать отдельные поддомены. Добавь их явно либо включи поддомены для корневого домена, не расширяя правило на посторонние сети.

## Управление из консоли

Посмотреть правила:

```powershell
.\vpn.cmd routes list --deployment home-vpn
```

В одиночной схеме (`single`) весь разрешённый трафик выходит через один сервер, поэтому `--outbound` не нужен:

```powershell
.\vpn.cmd routes add --deployment home-vpn --value example.com --include-subdomains
```

В двойной схеме (`dual`) выбор обязателен. Направить домен и его поддомены через российский сервер:

```powershell
.\vpn.cmd routes add --deployment home-vpn --value example.com --outbound direct-ru --include-subdomains
```

Направить домен через зарубежный сервер:

```powershell
.\vpn.cmd routes add --deployment home-vpn --value example.com --outbound to-foreign
```

Удалить правило по идентификатору из `routes list`:

```powershell
.\vpn.cmd routes remove --deployment home-vpn --id <rule-id>
```

На Linux замени `.\vpn.cmd` на `./vpn.sh`.

Наличие веб-панели определяется выбранной схемой, отдельного переключателя для её установки нет. Команды `routes` работают и без панели; в одиночной схеме они управляют правилами единственного сервера. Техническое устройство обработки правил описано в [PROJECT.md](./PROJECT.md).
