# VPN Installer

VPN Installer разворачивает личный VPN на одном или двух серверах. При установке выбирается одна из схем:

```text
один сервер: устройство -> VPN-шлюз -> интернет
два сервера: устройство -> российский VPN-шлюз -> зарубежный выход -> интернет
```

В одиночной схеме весь трафик выходит через выбранный российский или зарубежный сервер. В двойной схеме российские ресурсы используют российский IP, а остальной трафик выходит через зарубежный сервер. Во всех вариантах главный клиентский контракт один: `out/home-vpn/client/vless-uri.txt`.

В примерах `home-vpn` — наглядное имя установки. При первой установке оно уже предложено: нажми `Enter`, чтобы принять его, или введи другое имя.

Состав физических серверов фиксируется при создании deployment. Для перехода между одним и двумя серверами создай новое имя установки, проверь новый VLESS-путь и только затем удаляй старую установку; это исключает незаметно оставленный сервер или потерю доступа при переносе gateway.

## Быстрый старт

Потребуются:

- один сервер с `Ubuntu 24.04`, публичным IPv4, SSH-доступом и доступными TCP/UDP `443` для одиночной схемы;
- российский и зарубежный серверы с теми же базовыми требованиями и доступным межсерверным трафиком для двойной схемы;
- пользователь `root` либо пользователь с `sudo`;
- клиент с поддержкой `VLESS/Reality`.

Одиночная схема не устанавливает WireGuard, межсерверный transport или веб-панель и не требует их пакетов, портов, сервисов, ключей либо проверок. Эти зависимости появляются только в двойной схеме.

Проверенная пара провайдеров:

- российский сервер: [FirstByte](https://firstbyte.pro/?from=242253);
- зарубежный сервер: [iHor](https://ihor.online/?from=439652).

Другие варианты и требования к VPS: [как выбрать серверы](./docs/PROVIDERS.md).

Популярные совместимые клиенты:

- все основные платформы: [Happ](https://www.happ.su/main) или [Hiddify](https://hiddify.com/);
- Windows, macOS и Linux: [v2rayN](https://github.com/2dust/v2rayN);
- Android: [v2rayNG](https://github.com/2dust/v2rayNG), [NekoBox](https://github.com/MatsuriDayo/NekoBoxForAndroid), Happ или Hiddify;
- iPhone и iPad: [Streisand](https://apps.apple.com/app/streisand/id6450534064), Happ, Hiddify или платный [Shadowrocket](https://apps.apple.com/app/shadowrocket/id932747118).

Конкретное приложение не является частью серверного контракта: для основного подключения клиент должен уметь импортировать `vless://` с `Reality` и `XTLS Vision`. Используй актуальную версию выбранного клиента.

### Windows

Открой PowerShell в каталоге проекта и запусти:

```powershell
.\vpn.cmd
```

`vpn.cmd` является основной точкой входа для установки, обновления, проверки и удаления VPN.

При выборе SSH-ключа можно указать:

- пустое значение, чтобы использовать ssh-agent и стандартные ключи;
- имя файла, например `id_ed25519`, чтобы использовать `%USERPROFILE%\.ssh\id_ed25519`;
- полный или относительный путь к ключу.

Вместо ключа можно явно выбрать вход по SSH-паролю. Подробности: [запуск и диагностика на Windows](./docs/WINDOWS.md).

### Linux

```bash
chmod +x ./vpn.sh
./vpn.sh
```

Для запуска конкретной команды без меню:

```bash
./vpn.sh install --deployment home-vpn
./vpn.sh status --deployment home-vpn --node all
```

## Подключение

После успешной установки открой каталог `out/home-vpn/client`.

1. Импортируй `vless-uri.txt` в VPN-клиент. Это основной и обязательный профиль подключения.
2. Если клиенту нужен файл конфигурации, используй подходящий JSON из того же каталога.
3. `hiddify-uri.txt` и `v2rayn-uri.txt` содержат тот же основной VLESS URI и нужны только для удобства.
4. `hysteria2-uri.txt` предоставляет дополнительный вариант подключения для клиентов, которые его поддерживают; основной контракт остаётся в `vless-uri.txt`.

Краткие инструкции для конкретной установки записываются в `out/home-vpn/NEXT-STEPS.txt`.

## Основные команды

На Windows:

```powershell
.\vpn.cmd install --deployment home-vpn
.\vpn.cmd reinstall --deployment home-vpn --node all
.\vpn.cmd status --deployment home-vpn --node all
.\vpn.cmd verify live --deployment home-vpn
.\vpn.cmd diagnose path --deployment home-vpn
.\vpn.cmd maintain --deployment home-vpn
```

На Linux используй те же аргументы с `./vpn.sh` вместо `.\vpn.cmd`. Полный список доступен через:

```powershell
.\vpn.cmd --help
```

Для выбора узла используется только `--node gateway|exit|all`. Параметр `--role` и старые имена ролей в `0.20.1` не поддерживаются.

## Обновление 0.20.1

Установщик `0.20.1` допускает только три исходных состояния:

| Исходное состояние | Результат |
| --- | --- |
| VPN Installer ещё не установлен | Чистая установка |
| Установлен `0.20.0` | Единственный поддерживаемый переход на `0.20.1` |
| Установлен `0.20.1` | Повторная установка той же версии |

Минимальная совместимая установленная версия — `0.20.0`, максимальная — `0.20.1`. Любая другая версия отклоняется до изменения управляемых файлов. Для её удаления или полной очистки запусти `vpn.cmd`/`vpn.sh` именно из Git-тега установленной версии, выполни доступную в ней команду `remove` или `purge`, а затем установи `0.20.1` с нуля. Не используй новый установщик для удаления неподдерживаемого старого runtime.

Текущие форматы: `CONFIG_SCHEMA=3`, manifest/install-plan schema `4`, diagnostics schema `5`. Подробная граница совместимости: [переход с 0.20.0](./docs/DEPRECATIONS.md).

## Веб-панель

Веб-панель устанавливается только в двойной схеме и работает на публичном gateway. Команда печатает её адрес и при необходимости открывает браузер:

```powershell
.\vpn.cmd admin --deployment home-vpn --open-browser
```

Без `--open-browser` открой напечатанный адрес вида `http://<gateway-ip>:11333`. Firewall пропускает этот порт только для source IP, который недавно обращался к публичному TCP/UDP VPN ingress; допуск автоматически истекает. Это сетевой фильтр, а не замена авторизации. Начальный логин и пароль: `user` / `password`; сразу измени их на странице `Доступ`.

Типовые случаи:

- в двойной схеме российский онлайн-кинотеатр запрещает просмотр с зарубежного IP — направь его домен через `российский сервер`;
- банк, государственный сервис, маркетплейс, доставка или локальное медиа требует российский IP — выбери `российский сервер`;
- зарубежный сайт или сервис недоступен через российский выход — выбери `зарубежный сервер`;
- сервис использует несколько поддоменов — добавь `*.example.com` или включи поддомены.

В двойной схеме панель показывает российский и зарубежный выходы. В одиночной схеме web-admin отсутствует, но локальными правилами можно управлять через `vpn routes`. Правила применяются для всех клиентов VPN и не требуют повторного импорта профиля. При сохранении серверный router перезапускается, поэтому текущая загрузка может кратко переподключиться. Форматы правил, примеры и CLI-команды: [веб-панель маршрутизации](./docs/ADMIN.md).

## Если возникла ошибка

Сначала проверь состояние и полный пользовательский путь:

```powershell
.\vpn.cmd status --deployment home-vpn --node all
.\vpn.cmd verify live --deployment home-vpn
.\vpn.cmd diagnose path --deployment home-vpn
```

Интерфейс показывает краткую причину. Подробная информация сохраняется в:

- `out/logs/runtime/latest-error.log`;
- `out/logs/runtime/latest-transcript.log`;
- `out/diagnostics/`.

Разбор SSH-доступа и логов на Windows: [docs/WINDOWS.md](./docs/WINDOWS.md).

## Что даёт двойная схема

- **Один профиль для всех маршрутов.** Клиент подключается к российскому серверу по одному VLESS URI, а выбор российского или зарубежного выхода выполняется на серверах.
- **Российский и зарубежный IP одновременно.** Российские сервисы сохраняют доступ с российского адреса, а внешние ресурсы используют зарубежный выход без ручного переключения профилей.
- **Стабильная клиентская точка входа.** Изменения маршрутов и межсерверного транспорта не требуют заново настраивать каждое устройство, пока адрес и ключи российского входа остаются прежними.
- **Разделение узлов.** Российский gateway принимает клиентские подключения и применяет правила маршрутизации, зарубежный exit отвечает за внешний выход. Каждый узел можно обслуживать и проверять отдельно.
- **Резервирование связи между серверами.** Межсерверный путь поддерживает два транспорта и может восстановиться без изменения основного клиентского URI.
- **Полный контроль.** Конфигурация, журналы, диагностика и правила находятся на собственных серверах, а не у публичного VPN-провайдера.
